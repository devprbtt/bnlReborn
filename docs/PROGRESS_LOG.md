## 2026-10-19 - Replay seeks fold history; capability 12 rewinds in place

- Seeks no longer replay recorded history packet by packet. `ReplayCatchUp` folds the window into the state it leaves, using the client's own apply rules: unit, block and zone updates collapse to final values (ammo/devices/player stats/player info merge per key), movement and aim keep the newest sample, units and projectiles created and dropped inside the window are elided with their packets, only each builder's newest build event and each unit's newest landing/fall/tool toggle survive, destroyed blocks settle to air without replaying destruction, and effect-only packets (impacts, casts, damage numbers, attack visuals, pings, emotes) are skipped. Output is ordinary zone packets in 32 KiB acknowledged chunks; the viewer clock moves to the target first. Applies to every controls-capable client, so released clients benefit from a server deploy alone.
- Capability 12 rewinds without reloading the Zone scene: `ReplayWorld` tracks what the viewer's client holds (units, projectiles, block positions changed since the keyframe); a rewind drops those, replays the join snapshot and the folded stream to the target, and restores other touched blocks to their keyframe map value streamed from the recorded InitZone. After EndMatch/EndMatchResult a rewind still reloads. Playback at the final frame keeps serving seeks.
- Real recordings (828 s, 1331 s, 2709 s): skip build 372-430k packets -> 281-377; +/-10 s windows 9-31k -> 65-233; in-place -10 s rewinds 219-879 packets (<= 418 KiB), server 57-578 ms through 14 min, 2.1 s at the end of the 45 min match. Exact protocol round-trip on 12.3M unit, 66k block and 52k zone updates; folded state matches an independent oracle of the client apply rules; keyframe map index agrees with every first-touch block hit (21633/21633). Reproduce: `dotnet run --project tests/BNLReloadedServer.ReplayControlsFixture -c Release -- --recordings <files>`.
